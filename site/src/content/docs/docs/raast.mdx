## Reference

### createRaastP2PQr()

```ts
function createRaastP2PQr(options: {
  iban: string;
  amount?: number;
  expiresAt?: Date;
  expiresIn?: string | number; // e.g. '1d', '2h', or milliseconds
  bankName?: string;
  particulars?: string;
}): string;
```

**Returns** the QR payload text.

**Caveats.** Person-to-person QR codes use scheme `00`: banking apps reject the `30` in SBP's document. A QR with an amount needs `expiresAt` or `expiresIn`. Test-scan with your bank's app before using a QR for payments.

### parseRaastQr()

```ts
function parseRaastQr(payload: string): ParsedRaastQr | null;
```

**Returns** the decoded fields (IBAN, bank, amount, expiry), or `null` when the text is not a Raast QR.

### validateRaastQr()

```ts
function validateRaastQr(
  payload: string,
  options?: { now?: Date; expiresSoonMs?: number },
): RaastQrValidation;

interface RaastQrValidation {
  valid: boolean;
  kind: 'p2p' | 'merchant' | null; // null when the text is not a Raast QR
  errors: RaastQrError[]; // 'bad-checksum', 'no-iban', 'expired' …
  warnings: RaastQrWarning[]; // 'amount-ignored', 'expires-soon', 'no-iban'
  qr: ParsedRaastQr | null;
}
```

**Returns** whether a scanned QR is safe to pay: the CRC, IBAN checksum, amount and expiry, with readable problems, and the kind of QR.

**Caveats.** A merchant QR without an IBAN is valid, with the warning `no-iban`: merchant QRs may pay through the merchant's own scheme, so the payee can't be checked from the QR. A person-to-person QR without an IBAN is an error (`no-iban` in `errors`).

**Related:** [IBAN and banks](/docs/iban/), [`createMerchantQr()`](/api/typescript/raast/functions/createmerchantqr/).
